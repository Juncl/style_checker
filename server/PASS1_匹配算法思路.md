# Pass 1 全文本加权匹配 —— 算法思路

> 本文档是 `server/src/matchers/allTextMatcher.js` 的算法说明，供手写实现参考。
> 核心目标：把开发侧（ArkUI / hm）文本节点匹配到设计侧（Design / de）文本节点。

---

## 总览

整体分两大阶段：

1. **打分阶段**：开发侧主序，每个 hm 文本节点对所有 de 文本节点打分，得到 `finalScore`。
2. **三层匹配阶段**：基于打分结果，依次走 ① 种子锚点 → ② 迭代位移裁决 → ③ 全集无争议唯一对兜底。

关键参数：

| 参数 | 值 | 含义 |
|---|---|---|
| `CREDIBLE_THRESHOLD` | 0.9 | 可信阈值，只有 maxScore ≥ 0.9 的 hm 才进入种子/裁决机制 |
| `TIE_EPS` | 0.01 | 「拉不开差距」阈值（百分制 1 分）：候选与最高分相差 ≤ 此值算同档 |
| `RESOLVE_TIE_EPS` | 0.02 | 裁决「打平」阈值（按对角线归一）：最优与次优 cost 差 < 此值算裁决不出 |

置信度约定：

- **种子锚点 + ② 裁决出的节点** → `confidence: high`、`isAnchor: true`（强锚点）
- **③ 兜底配出的节点** → `confidence: low`、不作锚点

---

## 阶段一：打分（开发侧主序）

以 hm（ArkUI 开发侧）文本节点为外层主序，每个 hm **遍历全部** de（Design 设计侧）文本节点，用 5 个子评分加权出 `finalScore`：

| 子评分 | 说明 |
|---|---|
| 内容 | 编辑距离 + 语义 + 前后缀；数字归一化后相同视为内容一致 |
| 颜色 | 字色 ARGB 与白底混合后的距离；任一侧无值 → 1 |
| 字号 | 抛物线-高斯曲线 |
| 字重 | 抛物线-高斯曲线 |
| 位置 | 欧氏 + x 轴 + y 轴加权，顶部/底部对齐取较高 |

> 位置或字重子分为 0 → 一票否决，finalScore = 0。

每个 hm 记录：

- `maxScore`：最高分
- `maxScoreId`：最高分对应的 de id
- `compareDeIdS`：对**所有** de 的完整打分（deId → { finalScore, ... }）

> ⚠️ `compareDeIdS` 是对**全集**的打分，**没有**卡 0.9 阈值。后面第 ③ 层兜底要用到全集。

---

## 阶段二：三层匹配

全程用一个 `usedDe` 集合保证 **design 维度一对一**（一个 de 只能被一个 hm 占用）。

### 筛选

对每个 hm（**仅 `maxScore ≥ 0.9` 的参与**）：

```
topSet = { de 候选 | finalScore ≥ maxScore − TIE_EPS（且 ≥ 0.9）}
```

- `|topSet| == 1` → **不用裁决**（种子节点）：它只有唯一候选，归属确定、无歧义。
- `|topSet| ≥ 2` → **需要裁决**：进入未决集。

> **特例**：如果一个种子节点都没有（所有 ≥0.9 的 hm 都需要裁决）→ **放弃第二轮裁决**，未决节点全部落到第 ③ 层兜底。

---

### ① 种子锚点（topSet = 1）

种子节点直接归属它的唯一候选。

- 按 `maxScore` 降序处理；
- **design 维度去重**：如果两个种子节点的唯一候选撞上同一个 de，分高者占用，分低者本层落空（→ 落到第 ③ 层兜底）；
- 成功的种子 → 强锚点（high / isAnchor），**加入锚点池 `anchors`**。

> 种子节点之间**不需要互相裁决**：它们 topSet 唯一、无歧义，不存在「选哪个」的问题。它们的作用是充当后续裁决的**初始基准锚点**。

---

### ② 迭代位移裁决（topSet ≥ 2）

**前提**：必须已经有种子锚点（`anchors.length > 0`）才启动。

对每个待裁决 hm：

**第一步：挑 1 个参照锚点（pickAnchor）**

- 优先：锚点池里**与该 hm 的 Y 轴区间有交叠（同行 / 水平方向平行）**的锚点中，arkui 侧**距离最近的 1 个**；
- 退而求其次：如果没有同行锚点，就用 arkui 侧**欧式距离最近的 1 个**锚点。

> 只用 **1 个** 锚点，不是多个、不是加权。

**第二步：用这 1 个锚点的相对位移裁决候选**

对每个候选 de，算位移误差：

```
cost = |（hm 中心 − 锚点hm 中心）−（候选de 中心 − 锚点de 中心）| / diagonal
```

即比较「待裁决节点 → 锚点」在开发侧的相对位移，与「候选 de → 锚点对应 de」在设计侧的相对位移，**差最小的候选胜出**。

- 最优与次优 cost 差 `≥ RESOLVE_TIE_EPS` → **裁决出**，归属最优候选；
- 差 `< RESOLVE_TIE_EPS` → **打平**，本轮不裁决该 hm，留待下一轮。

**第三步：迭代滚雪球**

- **每一轮**：把所有**能裁决出来**的节点都定下来、占用其 de、**加入锚点池**；
- 每一轮裁决出来的节点**都**作为下一轮裁决的锚点（锚点池滚雪球式增大）；
- 不一定每轮都能裁决出节点（可能都打平）；但**只要某一轮有任意一个节点裁决出来，就再来一轮**；
- 直到**某一轮没有任何节点裁决出来**为止，停止。

> 打平的节点在后续轮可能被解开：锚点池变大后，pickAnchor 可能挑到更近/同行的新锚点，cost 不再打平。
>
> ② 收敛后仍未裁决出的节点 → 落到第 ③ 层兜底。

---

### ③ 全集无争议唯一对兜底（迭代到不动点）

兜底对象 = **所有仍未匹配的 hm**，包括：

- 第 ① 层种子撞车被挤掉的；
- 第 ② 层始终打平没裁决出的；
- 本来就 `maxScore < 0.9`、没进种子/未决集的。

**搜索范围**：在**整个 design 文本全集**上找（**不卡 0.9**，只要求 `finalScore > 0`）。

> 关键：不要局限在 topSet 或任何卡过 0.9 的初筛列表。要去**整个设计稿文本列表**里找它的唯一映射。
> `finalScore > 0` 只是排除「完全没关系」的 0 分对（位置极远 / 内容完全不搭），让「最高 / 唯一」有意义，**不是分数地板**。

**无争议对判定**（B = hm，D = de；均在**未占用 / 未匹配**子集上算）：

- **互为最高分**：B 的最高分候选是 D，**且** D 的最高分来源是 B —— **第一优先**；
- **一方唯一**：B 的候选只有 D 一个，**或** D 的来源只有 B 一个（哪怕另一方的 top1 不是它，因为这一方别无选择）。

满足任一 → 配 `B ↔ D`，**降级 low、不作锚点**。

**迭代到不动点**：

```
repeat:
  在「未占用 de / 未匹配 hm」集合上重建正向(hm→候选)、反向(de→来源)索引
  第一优先：把所有「互为最高分」的对配掉
            （若本轮有产出，重建索引再来一轮，先把互为最高分全配完）
  第二优先：再处理「一方唯一」的对（按分降序，高分先占，避免同轮撞同一 de）
  若本轮零产出 → 停止
```

> 占用是动态的：D 原本的最高来源 X 被别的 de 占走后，D 在「未匹配来源」里就可能升为 B 唯一 / 最高，新的无争议对逐渐浮现。
>
> 一直找不到无争议对的 hm → **不在 Pass 1 配**，交还后续 Pass 处理。

---

## 收尾

所有产出的 pair 过一道**锚点方位共识过滤**（`filterAnchorsByOrientation`）：踢掉与过半锚点方位矛盾的离群锚点（避免带偏后续拓扑），被踢的从可信映射中移除、降级为普通候选。

最终返回：`{ pairs, textHmMapPix, textHmMapPixCredible, textHmMapPixDetail }`。

---

## 死循环防御

② 和 ③ 两个迭代循环各加一道**硬轮数上限**作为保险：

- ② 上限 = `未决节点数 + 1`（每有效轮至少消耗 1 个未决节点）；
- ③ 上限 = `hm 文本节点数 + 1`（每有效轮至少匹配 1 个 hm）。

逻辑上两层都已收敛（每有效轮严格缩小未匹配集合），硬上限只是兜底，确保万无一失。

---

## 流程速查表

| 层 | 触发条件 | 裁决方式 | 产出置信度 |
|---|---|---|---|
| ① 种子锚点 | `topSet` = 1 | 直接归属唯一候选（design 去重） | high / 锚点 |
| ② 迭代位移裁决 | `topSet` ≥ 2，且已有种子锚点 | 单锚点（同行最近 / 欧式最近）相对位移，滚雪球迭代 | high / 锚点 |
| ③ 无争议唯一对兜底 | 所有仍未匹配的 hm | 全集上「互为最高分 / 一方唯一」，迭代到不动点 | low / 非锚点 |
