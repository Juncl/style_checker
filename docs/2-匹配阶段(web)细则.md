# Web 侧节点匹配细则

---

## 总流程

| Pass | 名称 | 产出 |
|---|---|---|
| Pass 1 | 全文本加权匹配 | 高置信文本锚点 |
| Pass 1.5 | 包含容器匹配 | 高置信容器锚点 |
| Pass 2 | 剩余节点兜底匹配 | 中低置信文本 + 非文本 |
| Pass 3 | 锚点一致性校验 + 盲匹配 | 剔除不可信、补充盲匹配结果 |
| 最终裁决 | selectOneToOnePairs | 一对一输出 |

---

## Pass 1 — 全文本加权匹配

dev 侧全部文本节点 × design 侧全部文本节点，全量两两打分。

**五维打分**：

| 维度 | 说明 |
|---|---|
| 内容分 | levenshtein 编辑距离 + 语义相似 + 前后缀加成 |
| 颜色分 | RGB 欧氏距离，先混白背景处理透明度 |
| 字号分 | Gaussian 曲线，容差约 4px |
| 字重分 | Gaussian 曲线，容差约 300 |
| 位置分 | 欧氏距离权重 0.6 + x 分量 0.3 + y 分量 0.1，顶对齐与底对齐各算一次取最大 |

**综合得分规则**：颜色、字号、字重完全一致且位置分 ≥ 0.9 时，内容分和位置分加权（内容权重降低，位置拉高至 0.6，加固定加成 0.25）；否则按五维标准权重加权。位置分或字重分为 0 时，综合得分直接归零。

**可信阈值**：综合得分 ≥ 0.9 → 高置信强锚点。

**后处理**：
- 八方位冲突率 > 50% 的锚点剔除（最多两轮迭代）
- 网格对齐检测：剔除打破行列对齐规律的异常锚点

**副产物**：全量两两打分详情，供 Pass 2 / Pass 3 盲匹配直接查询，避免重复计算。

---

## Pass 1.5 — 包含容器匹配

**触发条件**：Pass 1 存在至少一个强锚点。

以 Pass 1 强锚点为参照，在 dev / design 两侧各自找**包含该锚点**且**有视觉装饰**的祖先容器，尝试跨侧配对。

**一致性约束**：候选对必须与所有已有锚点保持包含关系一致——若某锚点被 dev 容器包含，则该锚点对应的 design 锚点也必须被 design 容器包含，反之亦然。

**打分**：IoU + 拓扑关系综合评分，贪心一对一裁决。高置信结果成为新锚点，参与后续 Pass 校验。

---

## Pass 2 — 剩余节点兜底匹配

处理 Pass 1 + 1.5 之后仍未匹配的 dev 节点与 design 节点。

**文本节点**：直接查询 Pass 1 已计算好的分数，无需重新计算。

**非文本节点**：三维几何打分：

| 维度 | 权重 | 说明 |
|---|---|---|
| 宽高比分 | 0.25 | Gaussian 曲线，对两侧宽高比差异建模 |
| 面积比分 | 0.25 | Gaussian 曲线，对两侧面积差异建模 |
| 位置分 | 0.50 | 复用 Pass 1 的位置评分逻辑 |

**置信度分级**：≥ 0.98 → 高，0.8 ~ 0.98 → 中，< 0.8 → 低。

---

## Pass 3 — 锚点一致性校验 + 盲匹配

### 3a. 前置预计算

对 Pass 2 后所有中低置信 pairs 的 dev 节点及未匹配 dev 文本节点，预计算其与每个高置信锚点之间的四态关系（包含 / 被包含 / 交叉 / 分离）和欧氏距离，按距离升序存储备查。

### 3b. 锚点一致性校验

以所有高置信 pairs 为锚点集，对每个中低置信 pair 做两道校验，任一不通过则判为不可信，释放其 dev 和 design 节点：

**① 包含一致性**（严格，任意一个锚点不通过即不可信）

对每个高置信锚点：dev 节点与 dev 锚点的四态关系，必须等于 design 节点与对应 design 锚点的四态关系。

**② 方位一致性**（宽松，冲突比例 > 50% 才不可信）

对每个高置信锚点：dev 节点相对 dev 锚点的八方位，与 design 节点相对 design 锚点的八方位，方位差 ≥ 3（超过 67.5°）记为冲突。

### 3c. 盲匹配

**待匹配节点**：不可信 pairs 释放的 dev 节点 + Pass 3 前未匹配的 dev 文本节点

**候选池**：不可信 pairs 释放的 design 节点 + 其他未匹配 design 节点

对每个待匹配 dev 节点依次执行：

1. 从预计算数据中取欧氏距离最近的 5 个锚点对。
2. 对每个锚点对，在候选池里过滤同时通过包含一致性（四态关系相等）和方位一致性（八方位差 < 3）的 design 节点，得到 5 组候选集。
3. 取 5 组的**交集**——交集为空则该节点本轮无匹配结果，无兜底。
4. 对交集节点打分（文本复用 Pass 1 分数，非文本用几何三维评分），取最高分者为候选。

按分数降序贪心一对一裁决。置信度分级同 Pass 2。

---

## 最终裁决

当同一节点被多个 Pass 竞争时，按以下综合优先级排序，高者优先：

> 置信度得分（高 300 / 中 200 / 低 100）+ 锚点加成（是锚点 +25）+ matchType 权重 + 拓扑得分 × 10 + IoU 得分 × 8（仅非文本对）

**matchType 优先级**：

| 来源 | matchType | 权重 |
|---|---|---|
| Pass 1 | text-锚点 | 40 |
| Pass 1.5 | text-con-包含 | 32 |
| Pass 2 | text-con-web匹配 | 16 |
| Pass 3 | text-con-盲匹配 | 12 |

同优先级时依次按：background 颜色是否一致 → design path 顺序 → dev path 顺序决胜。最终结果按 design path 顺序输出。
